# Design and safety

The pipeline is explicit:

```text
input -> reader -> document -> chunking -> prompt/profile
      -> local engine -> aggregation -> formatter -> stdout
```

Each stage is independently testable; the CLI stays thin and the pipeline owns
the ordering and the security-scoped prompt construction.

## The trust boundary

Document text is untrusted data. For every model request it is placed in a
fresh, cryptographically random XML-like boundary, separate from trusted
security instructions and the selected profile.

Randomness alone is not treated as sufficient: before wrapping content, the
tool checks whether the exact boundary token already appears in any content it
will enclose (the document or the trusted context file) and regenerates on a
collision, so literal attacker-created boundary-shaped text cannot close the
region early. If no safe token can be found it refuses to build the prompt
rather than emit a forgeable one. The user's document on disk is not modified.

## Map-reduce intermediates are untrusted

Map-reduce intermediate summaries are **untrusted intermediate data**. The
reduce prompt treats every interim summary exactly like document content,
wrapping each in its own per-round boundary. The reduce instructions are a
separate, structurally distinct trusted section; the tool does not rely on the
fact that the intermediate text was generated by its own model.

## `--context` is trusted by you

`--context FILE` is explicitly trusted by *you*: it is never mixed with the
document and receives its own labelled `USER-SUPPLIED CONTEXT (TRUSTED)`
section. Only use a context file whose origin you trust — its content is
treated as instructions, unlike the document. Context content is still
boundary-checked so it cannot forge the document boundary.

## Prompt-injection resistance is not claimed to be solved

The boundary, collision handling, and structural separation are
**defence-in-depth**: they make the delimiter unforgeable and keep untrusted
text out of the trusted instruction sections. They cannot stop a model from
following persuasive text inside the region. Whether a model honours the
contract remains probabilistic — it can still summarize maliciously,
hallucinate, or quote hostile text. The adversarial corpus treats an echoed
injected token as a signal for review, not proof of failure.

The blast radius is bounded: model output is printed or emitted as JSON and
nothing else. There is no tool execution, network access, file write, or shell
driven by model output, so the worst case is a wrong summary. Feeding the JSON
into an automated consumer changes that, so validate it there.

## Aggregation and chunking

Oversized input is budgeted against the model's *discovered* context window,
then chunked at paragraph/sentence/word boundaries with overlap and summarized
via map-reduce. Chunk provenance (source, index, offsets, boundary) is
preserved. See [readers.md](readers.md) for the JSON schema and
[performance.md](performance.md) for concurrency and checkpoints.

## Output discipline

All diagnostics, progress, and warnings go to stderr; stdout contains only the
summary or requested JSON. `-o FILE` writes through a same-directory temporary
file and atomically replaces the destination only after a successful result.
